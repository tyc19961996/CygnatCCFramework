# 233 APK 原生广告设计

233 乐园 Android 渠道包沿用现有 `Core.Platform` 和 `MiniGame.MiniHelper.ad()`。Creator 原生 Android 包带有框架的 Java 桥接类时识别为 `PlatformType.Apk233`，同时保留 Android 系统标记。普通 APK 继续使用既有识别方式。`common()` 由 `BaseCommon` 提供，支付沿用默认行为。

参考鸿蒙的同步反射和请求编号，TypeScript 提交广告操作并排空事件队列，Java 在主线程初始化和调用官方 SDK。游戏通过现有 `init` 对象传入 appKey 和后台分配的整数广告位。激励收到奖励且关闭后才回调成功。插屏展示后关闭才成功。失败和超时均结束当前业务请求。SDK 的同类型全屏回调槽在旧请求终态前保留，避免迟到回调结算到新请求。Banner 使用显式广告位配置，显示成功与关闭分别通知，隐藏和销毁都调用原生关闭。平台当前关闭了 Banner 流量，默认配置不含 Banner 广告位。

接入使用可随框架打包的 Java 源文件，由游戏工程添加官方 AAR 并接上 Activity 生命周期。验收包括平台隔离、各广告的成功与失败、早退、晚到和重复回调、原生签名编译和打包内容检查。平台实播使用 233 自测工具和关联了广告位的 APK。
