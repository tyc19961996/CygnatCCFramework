# 小游戏系统信息公共接口设计

## 目标与现状

将现有 `getSystemInfo` 从平台内部能力开放到 `IMiniCommon` 和 `MiniHelper.common()`。微信、支付宝、Bilibili、快手、抖音和 OPPO 已有同步取值与缓存；基类和鸿蒙没有对应方法，鸿蒙现有桥接也没有系统信息命令。

## 方案与范围

六个平台把方法改成 `public`，保持原生返回对象、具体类型、缓存与错误处理；微信、支付宝、Bilibili、快手和抖音明确声明 `| null`，使严格空值检查的消费方处理原有失败返回。OPPO 仍保持原有空对象兜底。基类新增返回 `null` 的方法，鸿蒙继承该兜底。新增 `MiniSystemInfo`，用可选字段描述常用系统和屏幕信息，不补造缺失数据；平台专用字段仍可通过具体适配器类型访问。

比较直接返回六个平台类型联合和独立通用类型：联合类型不便访问各平台缺失的字段，因此采用通用可选字段；平台类保留原具体返回类型。不引入异步接口或额外的鸿蒙原生桥接，保持发布出口；经用户授权，随本次提交将包版本提升到 `0.3.11`。

## 兼容性与公共导出

`IMiniCommon.getSystemInfo?(): MiniSystemInfo | null` 沿用已有新增方法的可选约定，兼容旧的结构化实现；`MiniHelper.common()` 通过现有 `Required<Pick<...>>` 保证内置适配器可直接调用。`MiniSystemInfo` 从 `MiniGame/index.ts` 经根命名空间公开。宿主声明及其复制脚本已有六个平台的同步接口，无需新增宿主 API。

## 验证

先验证类型测试因私有方法、公共类型和接口缺失而失败，运行时测试因基类缺失方法而失败。实现后检查六个平台返回宿主原对象且缓存只取一次，基类及鸿蒙返回 `null`；检查公共调用、具体返回类型和旧结构兼容。执行完整 `npm test`、`npm run build`、`npm run pack:check` 与 `git diff --check`，检查生成声明。测试使用转译源码和最小宿主 stub，不替代真机验证。
